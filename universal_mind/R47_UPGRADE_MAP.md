# R47 — نقشهی جهش: «داورِ زنده، پیشگوی معنایی، روزِ دیدنی، پیکربندیِ نفَس»

> تداوم R43→R44→R45→R46. اصل حاکم همان است: **سیستمی که با چشمِ خودش
> سنجیده میشود به سقفِ خودش میرسد** — هر قلم یا حلقه در این راند یا یک
> سیگنالِ خارجیِ واقعی وارد پلتفرم میکند، یا دادهی موجودِ مرده را به
> ادراکِ زنده تبدیل میکند.

## خط پایه (اندازهگیریِ واقعی، قبل از نوشتن)
- تست: ۱۶۲۴ سبز؛ probe: ۱۰۶؛ VERIFY=0؛ کامیت `ad0e157`
- llm capability موجود (env: UM_LLM_BASE_URL/UM_LLM_KEY) — داوری ARETĒ از آن بیخبر است
- predictor = شمارش route در run_history؛ معنای فرمان را نمیفهمد
- advisor semantic (TF-IDF) هست ولی predictor از آن استفاده نمیکند
- probe_r46_day یک PDF میسازد؛ هیچ HTML زندهی «امروز» وجود ندارد
- unknown_terms: ۶ واژه (همه آزمون؛ آمادهی پاکسازیِ دورهیای)

## فاز ۱ — داورِ زنده (۳ قلم) 🟢 «موج اول: قضاوتِ دوم از بیرون»

- [ ] **۱. داورِ LLM در ARETĒ** — پیشنیاز: هیچ.
  `arete/live_judge.py`: یک `ExternalJudge` جدید که همان فرمولی ARETĒ
  را با نگاهِ یک مدلِ زنده cross-check میکند: فرمان + گزارش + رأی
  فرمولی → LLM به آن **نمرهی مستقل** میدهد (۰..۱) + یک خط دلیل.
  بدون env → **داوری LLM صادقانه رد میشود** (نه mock، نه تقلب). نتیجه
  در جدول `live_judgments` (command, formula_score, llm_score, reason,
  created_at) + وقتی اختلاف > ۰.۳ است، گزارش یک خط هشدار میگیرد.
  معیار زنده: با env واقعی → ردیفِ دو-نمرهای؛ بدون env → «داورِ زنده
  در دسترس نیست» صادقانه.
- [ ] **۲. خطِ داورِ زنده در گزارش** — پیشنیاز: قلم ۱.
  persian_report یک خطِ «⚖ داورِ زنده: ۰.۸۷ — دلیل» اضافه میکند وقتی
  LLM قضاوت کرده است؛ در نبودِ env، خط نمینویسد (سکوتِ صادق).
  معیار زنده: ران با env → خط ⚖ در گزارش؛ ران بدون env → خط نیست.
- [ ] **۳. داورِ زنده در tick (نمونهگیری)** — پیشنیاز: قلم ۱.
  هر tick یک رانِ موفقِ امروز را (حداکثر یکی، تصادفی) به داورِ زنده
  میفرستد؛ نتیجه در tick summary چاپ و در live_judgments ردیف میشود.
  معیار زنده: tick با یک رانِ امروز → یک قضاوتِ زندهی جدید.

## فاز ۲ — پیشگوی معنایی (۳ قلم) 🟠 «موج دوم: پیشبینی از معنا، نه شمارش»

- [ ] **۴. predict از معنا** — پیشنیاز: هیچ.
  success_predictor: وقتی TF-IDF advisor نزدیکترین فرمانِ گذشته را
  با شباهتِ بالا (≥۰.۵) مییابد، نرخِ موفقیتِ آن «معنای مشابه» به
  پیشبینی میپیوندد (وزن‌دار با شمارشِ route). Prediction نقطهی
  `semantic_anchor` و `similarity` میگیرد.
  معیار زنده: seed دو فرمانِ مشابه → پیشبینی برای فرمانِ سومِ مشابه
  از anchor استفاده میکند و جزئیاتش را میگوید.
- [ ] **۵. سوالِ پیشِ ران: «آیا این کار میشود؟»** — پیشنیاز: قلم ۴.
  «آیا ... کار میکند؟» / «احتمالش چقدر است؟» → پاسخ گفتاری از
  Prediction واقعی (bar، نرخ موفقیت مشابه، دلیل anchor) — بدون اجرا.
  معیار زنده: seed + پرسش → پاسخ حاوی بارِ واقعی و نامِ anchor.
- [ **۶. ترمیمِ از پیش گفتهشده** — پیشنیاز: قلم ۴.
  predictor ضعیف + anchor موجود → gate از همان ابتدا رقیبِ پیشنهادیِ
  semantic را هم امتحان میکند (نه فقط reorder) — و در reasoning
  میگوید «پیشبینی ضعیف بود؛ رقیبِ معنایی X را امتحان کردم».
  معیار زنده: مسیرِ ضعیفِ seedشده → gate رقیبِ semantic را میراند و
  در gate_reasoning اسمش میآید.

## فاز ۳ — روزِ دیدنی (۳ قلم) 🔵 «موج سوم: امروز در یک صفحه»

- [ ] **۷. صفحهی «امروز» HTML زنده** — پیشنیاز: R46 (probe_r46_day).
  `today_page.py`: یک HTML تک-صفحهی فارسی RTL از دادهی واقعی امروز —
  بریفینگ، رانهای امروز (فرمان/مسیر/داوری/مهر تأیید)، یادآورهای امروز،
  حافظهی نامی، تپش، سیگنال قرمز — تمیز و مینیمال، با اعداد فارسی؛
  فایل در store dir نوشته میشود و مسیرش گفته میشود.
  «صفحهی امروز را بساز» → مسیر فایل.
  معیار زنده: seed → فرمان → فایل HTML با همهی بخشها و مسیر واقعی.
- [ ] **۸. صفحهی امروز در tick** — پیشنیاز: قلم ۷.
  tick صفحهی امروز را بازسازی میکند (بعد از بریفینگ) — هر روزِ فعال
  یک صفحهی تازه دارد؛ مسیرش ثابت است (today.html).
  معیار زنده: tick → today.html با mtime تازه و محتوای امروز.
- [ ] **۹. خداحافظیِ کامل: «جمعبندیِ روز»** — پیشنیاز: قلم ۷.
  «جمعبندی روز» → خداحافظی + جمعبندی سهخطیِ واقعیِ امروز (رانها،
  موفقیتها، قضاوتهای زنده) + رانِ PDF «یک روزِ کامل» اگر خواستی.
  معیار زنده: seed → «جمعبندی روز» → پاسخ حاوی شمارشِ واقعی + 🌙.

## فاز ۴ — پیکربندیِ نفَس (۳ قلم) 🔴 «موج چهارم: یادگیریِ بیسکوت»

- [ ] **۱۰. تلماس‌ها از واژههای واقعی** — پیشنیاز: R46-9.
  unknown_terms پاکسازی دورهیای (آزمونها حذف) + «واژههای ناشناخته را
  پیشنهاد بده» → برای هر واژهی پرتکرار (hits ≥ ۳): «شاید منظورت
  قابلیت X بود؟» با نزدیکترین قابلیت از روی فاصلهی ویرایش (levenshtein
  ساده) + دکمهی گفتاری «یعنی X».
  معیار زنده: seed واژهی پرتکرار نزدیک به «نمودار» → پیشنهاد درست.
- [ ] **۱۱. درصدِ رشد یادگیری** — پیشنیاز: قلم ۱۰.
  «چقدر یاد گرفتی؟» → درصدِ واژههای ناشناختهای که مشابه معنادار
  پیدا کردهاند (تعریفشده، پیشنهادشده، یا حل‌شده) از کلِ شکارشدهها؛
  از جدولهای واقعی (learned_vocab, unknown_terms) — یک عددِ رو به رشد.
  معیار زنده: seed mixed → درصد دقیق از جدولها.
- [ ] **۱۲. probe «ذهنِ همسایه»** — پیشنیاز: همه.
  probe_r47_mind.py: یک seed کامل → فرمانهای واقعی → داوری زنده (اگر
  env) → پیشبینی معنایی → صفحهی امروز → پیشنهاد واژه → درخواست
  «چقدر یاد گرفتی؟» → همه در یک PDF «ذهنِ در حالِ رشد».
  معیار زنده: probe سبز = هر ۱۱ قلم قبل از خودش در یک گذر زنده.

## ترتیب اجرا (اثر ÷ ریسک) و قاعدهی پذیرش

موجها به ترتیبِ فاز؛ در هر موج از بالا به پایین. **قاعدهی پذیرش هر قلم
(بدون استثنا):** پیادهسازی با الگوی پروژه → تست سبز → شاهد زنده (فرمان
واقعی از route_and_run یا probe مستقل، خروجی واقعی چاپشده) → ruff پینشده
تمیز → mypy ratchet 0≤0 → فول pytest سبز → probe جدید در verify.py/Makefile
→ کامیت ایزوله. یک موج = یک کامیت؛ هیچ قلمی نیمهکاره رها نمیشود.
