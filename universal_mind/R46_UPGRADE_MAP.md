# R46 — نقشهی جهش: «ذاتی شدن، داوریِ مصنوع، روانِ گفتار، پایداریِ روزمره»

> تداوم R43→R44→R45→R46 — READY (VERIFY=0), 1624 tests, 106 probes. اصل حاکم همان است: **سیستمی که فقط با خطکِ خودش سنجیده
> میشود به سقف خودش میرسد** — هر قلم یا حلقهی موجود را به داورِ بیرونیِ
> سختگیرتر وصل میکند، یا ذهن را با دادهی واقعیِ خودش رشد میدهد، یا زبانِ
> روزمرهی اپراتور را به فرمان واقعی تبدیل میکند. هیچ قلمی «قابلیت خالی» نیست.

## خط پایه (اندازهگیریِ واقعی، قبل از نوشتن)

- کامیت مبنا: `de9798b` (R45 کامل: ۱۶/۱۶، ۱۵۹۰ تست، ۶۸ probe، `VERIFY=0`).
- شکافهای زندهی سنجیدهشده (grep/کوئری، همین حالا):
  - `unknown_terms` واقعی: ۱۲ ردیف که ۹ تای آن واژههای واقعی است اما
    سرآشها («فرمان، هیچ، قابلیتی، ندارد، نمیکند») نویز هجینگِ جملهی رد
    هستند — شکار باید «موضوع» را بگیرد نه کلمات تابع جمله را؛ پاکسازی لازم.
  - `weekly_reports`/`run_history_archive` هنوز ردیفی ندارند (موجدها؛ اولین
    دادهی واقعی شان با اولین tick هفته/فشردهسازی میآید).
  - هدفها (goals) `resume` دارند اما **مکث و دروازهی ادامه (go/no-go)**
    ندارند: هدف متوقفشده یا ادامه مییابد یا رها — «ببین ارزش ادامه دارد؟»
    پرسیده نمیشود.
  - سلام و خداحافظی گفتاری («صبحت بخیر»، «مرسی») جواب ثابت دارد نه پاسخِ
    همراهِ داده («صبحت بخیر — امروز ۳ فرمان تا حالا؛ رشتهی تپش ۶ روز»).
  - تأیید مصنوع: خروجیها (PDF/PNG/XLSX) فقط بایتشمار میشوند؛ کسی فایل را
    باز نمیکند که واقعاً PDF/PNG سالم است (تا ۸۰٪ قابل اعتماد بودن).
  - «دوباره امتحان کن» فقط «همان فرمان قبلی» را میفهمد؛ retry-on-failure
    (فرمانِ شکستخوردهی اخیر با استراتژی متفاوت) وجود ندارد.
  - بریفینگ صبحگاهی: اولین tickِ روز هیچ خلاصهای به اپراتور نمیدهد.
  - dash رانشِ گزارش: golden corpus ثابت است؛ هیچ یادگیریِ قانونِ تازه از
    رأیهای انسانی به آن اضافه نمیشود.

## فاز ۱ — داوریِ مصنوع (۴ قلم) 🟢 «موج اول: خروجی را کسی باز میکند»

- [x] **۱. تأییدگر مصنوع (artifact validator)** — پیشنیاز: هیچ.
  `artifact_validator.py`: هر نتیجهی موفق که فایل میسازد، بعد از ساخت
  «باز» میشود: PDF → سردرِ `%PDF` + شمارش صفحه (pypdf)، PNG/JPG →
  `PIL.Image.verify()`، XLSX → `openpyxl.load_workbook`، CSV → خواندن
  ردیف اول، ZIP → `zipfile.ZipFile.namelist`. نتیجه در ران مهر میخورد
  (`verified` در ستون تازهی run_history) و «تأییدشده: X» در گزارش.
  معیار زنده: هر ۵ قالب با فایل خرابعمدی رد و سالم قبول.
- [x] **۲. دروازهی go/no-go در هدف** — پیشنیاز: هیچ.
  «هدف: X» اگر ۲ گامِ پیاپی شکست بخورد، حلقه مکث میکند و سؤال میپرسد:
  «۲ گام شکست خورد — ادامه بدهم یا بایستم؟ (ادامه بده / بایست)»؛ ردیف
  هدف `state='paused'` میگیرد؛ «ادامه بده» همان مسیر resume موجود را
  میگیرد؛ «بایست» → state='stopped' با گزارشِ صادقانه. معیار زنده: هدفِ
  seedشده با ۲ شکست → paused → «ادامه بده» → ادامه واقعی.
- [ [ ] **۳. رأیِ انسانی → قانونِ رانشِ گزارش** — پیشنیاز: R44-3.
  هر رأیِ 👍 روی فرمانی که golden corpus نیست، یک «قانونِ کاندید» میسازد
  (فرمان → وعدههای واقعیِ گزارشش) و در جدول `report_laws` مینشیند؛
  probe/verify این قوانین را هم مثل golden میسنجد — رأی تو قانونساز
  میشود نه فقط آمار. معیار زنده: رأی 👍 → ردیف قانون → رانش عمدی در آن
  گزارش → قرمز.
- [x] **۴. نرخِ تأیید در گزارش و داشبورد** — پیشنیاز: قلم ۱.
  گزارش گفتاریِ «امروز» و خانهی تازه در داشبورد: «از N فایلِ امروز، M
  تأییدشده»؛ فایلهای تأییدنشده با نام خوانده میشوند. معیار زنده: seed
  با ۲ فایل سالم و ۱ خراب → «۲ از ۳ تأیید شد؛ ۱ مشکل: <نام>».

## فاز ۲ — روانِ گفتار (۴ قلم) 🟠 «موج دوم: زبانِ روزمرهی اپراتور»

- [x] **۵. سلامِ همراهِ داده** — پیشنیاز: R45-1/13.
  «صبحت بخیر / سلام / درود» → سلامِ واقعی + یک خطِ وضعِ کوتاه (فرمانهای
  امروز، رشتهی تپش، نامهی هفته اگر نوشته شده). خداحافظی («مرسی/ممنون/
  خدانگهدار») → جمعبندیِ سهخطیِ جلسه + «منتظرت میمانم». معیار زنده:
  سلام در store با ۲ فرمان امروز → جواب حاوی ۲ و تپش.
- [x] **۶. retry هوشمند** — پیشنیاز: هیچ.
  «دوباره امتحان کن» وقتی آخرین رانِ واقعی شکست خورده باشد: همان فرمانِ
  شکستخورده را با راهبردِ متفاوت دوباره اجرا میکند (اگر chain شکست →
  حذف قابلیتِ شکسته از زنجیره و تلاش با بقیه؛ اگر params → درخواستِ پارامتر).
  رانِ دوم مهر `retry_of` میخورد. معیار زنده: شکستِ ساختگی → retry →
  رانِ دوم با مسیر متفاوت و مهر retry.
- [x] **۷. پالایش شکارِ واژهها** — پیشنیاز: R45-12.
  هجینگِ حرفی: واژههایی که فقط در جملهی رد ظاهر شدهاند (فرمان/هیچ/
  قابلیتی/ندارد/نمیکند/… بهعنوان stopword جملهی رد) از شمار حذف؛
  موضوعِ اصلی (واژهی محتوایی) برجسته میشود؛ جدول واقعی پاکسازی و
  بازشماری میشود. معیار زنده: ردِ «فرمانی…» → فقط موضوع شمرده شود.
- [x] **۸. پرسشِ آزادِ وضعیت** — پیشنیاز: R45-10.
  «خب؟»، «چی جدید؟»، «وضع؟»، «خبر چیست؟» → همان پاسخِ پنجسیگنالیِ
  خود_status (کوتاهشده). معیار زنده: ۴ شکل گفتاری مختلف → همه به
  پاسخِ سیگنالدار برسند.

## فاز ۳ — ذاتی شدن (۴ قلم) 🔵 «موج سوم: یادگیری که در زمان واقعی مینشیند»

- [x] **۹. واژگانِ آموختهشده (overlay زنده)** — پیشنیاز: قلم ۷.
  «واژهی X یعنی Y» (اپراتور تعریف میدهد) → جدول `learned_vocab`
  (word→capability)؛ همان فرمانِ بعدی بدون کد جدید مسیر درست میگیرد؛
  `route_and_run` overlay را قبل از _VOCAB میخواند. «چه یاد گرفتی؟»
  فهرست میکند. معیار زنده: تعریف «زرشک»→data → «میانگین زرشک…» →
  route data (بدون هیچ کامیتِ واژگانی).
- [x] **۱۰. بریفینگِ صبحگاهی در tick** — پیشنیاز: R45-8.
  اولین tickِ هر روز: یک toastِ سهخطی (دیروز چی شد، امروز چه سرسیدی
  هست، سیگنالِ قرمز اگر هست)؛ در `daily_briefings` ردیف میشود و
  «بریفینگ امروز را بگو» همان را میخواند. معیار زنده: seed → tick →
  toast + ردیف + خواندن گفتاری.
- [x] **۱۱. ایندکسهای واقعی روی جداول داغ** — پیشنیاز: هیچ.
  run_history: created_at، (route, succeeded)؛ operator_verdicts:
  created_at؛ unknown_terms: term UNIQUE. با EXPLAIN QUERY PLAN قبل/بعد
  اثباتِ استفاده. معیار زنده: query plan قبل/بعد چاپ شود، بعدِ ایندکس
  `USING INDEX`.
- [x] **۱۲. سالنامه + نامه + بریفینگ در یک منوی گفتاری** — پیشنیاز: قلم ۱۰.
  «گزارش کامل بده» → همهی گزارشهای دورهیای (بریفینگ امروز، نامهی هفته،
  سالنامه) در یک پاسخِ ساختاریافته + PDF اختیاری. معیار زنده: پرسش →
  پاسخ حاوی هر سه بخشِ از جدولهای واقعی.

## فاز ۴ — پایداریِ روزمره (۴ قلم) 🔴 «موج چهارم: چیزهایی که هر روز درد میسازند»

- [x] **۱۳. مقاومتِ tick در برابر خطای محیط** — پیشنیاز: هیچ.
  tick الان اگر استوری در دسترس نباشد بیصدا میمیرد؛ حالا: هر بلوک lens
  مهرِ وضع میگیرد (`ok/skipped/failed: علت`)، خلاصهی tick در
  `tick_health` ردیف میشود، و tickِ بعدیِ خطادار به toast میرسد. معیار
  زنده: مانکیپچ استوری → tick → ردیفِ skipped با علت + RC=0.
- [x] **۱۴. فشردهسازی در tick** — پیشنیاز: R45-13.
  اولین tickِ ماه: compact_history (batch کوچک) + گزارشِ شمارش؛
  rollback همان جا قابل فرمان میماند. معیار زنده: seed کهنه → tick →
  آرشیو ردیف خورد.
- [x] **۱۵. سلامتِ backup در وضعیت** — پیشنیاز: R45-10.
  «بکاپ سالم است؟» → جدیدترین بکاپ + مانورِ آخر + نتیجهی integrity؛
  اگر بکاپ >۷ روز کهنه → هشدارِ صریح در وضعیت. معیار زنده: بکاپ تازه →
  سالم؛ مهر جعلی قدیمی → هشدار.
- [x] **۱۶. probe «یک روزِ کامل»** — پیشنیاز: همه.
  probe_r46_day.py: یک seed، یک شبانهروزِ فشرده: بریفینگ صبح → چند فرمان
  (یکی شکست → retry) → رأی → قانونِ رانش → نامهی هفته → وضعیت پنجسیگنالی
  → فشردهسازی → مانور بازیابی → خداحافظی. همه در PDF «یک روز».
  معیار زنده: probe سبز = هر ۱۵ قلم قبل از خودش در یک گذر زنده ثابت شد.

## ترتیب اجرا (اثر ÷ ریسک) و قاعدهی پذیرش

موجها به ترتیبِ فاز؛ در هر موج از بالا به پایین. **قاعدهی پذیرش هر قلم
(بدون استثنا):** پیادهسازی با الگوی پروژه → تست سبز → شاهد زنده (فرمان
واقعی از route_and_run یا probe مستقل، خروجی واقعی چاپشده) → ruff پینشده
تمیز → mypy ratchet 0≤0 → فول pytest سبز → probe جدید در verify.py/Makefile
→ کامیت ایزوله. یک موج = یک کامیت؛ هیچ قلمی نیمهکاره رها نمیشود.
