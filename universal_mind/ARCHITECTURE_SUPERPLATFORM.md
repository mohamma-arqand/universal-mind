# نقشهٔ معماری — «Universal Mind» ابرپلتفرمِ خودگردان

> **سند زنده — آخرین وضعیت واقعی سیستم.** هر بخش با شمارهٔ commitی که آن را
> ساخت پشتیبانی می‌شود؛ چیزی در این سند «طرح» نیست که ساخته نشده باشد.

---

## ۰. اصل حاکم

جذب دو وجه دارد: **اتصال** (هر ابزاری از داخل پلتفرم فراخوانی می‌شود) و
**جذبِ واقعی** (قابلیتِ ابزارهای باز داخل سیستم بازنویسی می‌شود). قانون
طلایی: هر ابزار اول «وصل» می‌شود؛ اگر باز بود، «جذب» می‌شود. پلتفرم هیچ
ابزاری را جا نمی‌گذارد.

نتیجهٔ عملیِ امروز: **۱۳ قابلیتِ واقعی، ۱۱۵+ عملیات، ۹ جریانِ سنتز** —
همهٔ پشت یک موتور واحد، همهٔ با قواعد صداقتِ تست‌شده.

## ۰.۵. عامل (لایهی فرمان) — هدفهای چندگامی

```
«هدف: میانگین ۱۰ و ۲۰ را حساب کن و نمودارش کن و گزارش کامل بساز»
→ goal_parser: گامها (لیستهای عددی محفوظ، سپس/و جداکننده)
→ agent_loop: هر گام با route_and_run + داوری ARETĒ
   گام ضعیف → یک ترمیم (quality gate) → اگر هنوز ضعیف: توقف صادقانه در همان گام
→ پیشرفت ماندگار (جدول goals) → قابل ادامه («ادامه بده» از گام شکست)
→ CLI: universal-mind goal "هدف: ..."
→ پنجره: تب «اهداف» (ثبت، اجرا، ادامهی همهی متوقفشدهها)
→ عامل در ساعت: «هر روز ساعت ۸ هدف: ...» — یک جمله، دو لایه (زمانبندیشده؛
  tick آن را فایر میکند و عامل گامها را تازه دنبال میکند)
→ probe: probe_agent_loop + probe_autonomous_agent (در verify)

قواعد صداقتِ عامل: گام شکست → توقف در همان گام (نه مارش کور)؛ ترمیم فقط
یکبار؛ ادامه از همان گام؛ فرمان عادی هرگز hijack نمیشود (مارکر «هدف:» صریح است).

**گام شرطی** — «اگر X موفق بود، Y»: Y فقط وقتی ARETĒ گام قبل را ok گفت.
شکستِ X → Y صادقانه «رد شد» و هدف ادامه مییابد (فلسفهی guard واکنش به
شکست است نه توقف). بدون guard بعد از شکست، توقف همانند قبل.

**فرمانهای یککلمهای عامل:** «ادامه بده» (ازسرگیری همهی متوقفها از همان
گام)، «وضعیت» (تختهی همهی هدفها با آخرین داوری) — و tick خودش هدفهای
متوقف را در toast نام میبرد («در انتظارِ ادامه بده»).



### ۰.۵.۱. شش جهش (نقشه، گرمی، خود-آزمایی، نشست، پیشبینی، حلقهها)

| جهش | ماژول | چه میکند |
|---|---|---|
| نقشهی هدف (DAG) | `goal_map.py` | گامها با «بعد از گام N» موازی میشوند؛ join منتظر همه؛ چرخه صادقانه رد |
| گرمکردن | `scheduler_tick.py` | tick مسیرهای داغ را پیش-گرم میکند — اولین فرمان روز فوری |
| خود-آزمایی tick | `scheduler_tick.py` | هدفهای هرگز-شروع-نشده نامبرده میشوند (خود-بازبینی؛ بدون re-run کور) |
| هستهی نشست | `session_core.py` | یک context سراسری: شمارندههای اتمیک نشست در-جریان؛ سه چهره یک عدد زنده |
| ARETĒ پیشبین | `success_predictor.py` | پیش از اجرا: احتمال Laplace از تاریخچه → آستانهی داوری پویا (قوی ۷۵٪ / پرریسک ۹۰٪) |
| حلقههای داده | `orchestration.py` | هیستوگرام از اعداد جمله؛ excel→chart (خواندهشده رسم میشود) |

## ۱. موتور (یک مسیر، پنج مرحله)

```
فرمان فارسی (هر ترتیبِ واژه)
  ↓ ۱. توصیهگر        — از داوری‌های ARETĒ تاریخچه + زنجیره‌های ذخیره‌شده
  ↓ ۲. برنامه‌ریز      — ترتیب از نیازهای واقعی عملیات‌ها (توپولوژی)،
  │                      عملیات از درس‌های اثبات‌شده (جدولِ به‌دست‌آمده)
  ↓ ۳. اجرا            — orchestrate با ۹ جریانِ سنتز بین برنامه‌ها
  ↓ ۴. دروازهٔ کیفیت    — داوری ضعیف → خودترمیمی از مسیر رقیب
  ↓ ۵. داوری ARETĒ     — چهار فضیلت از دادهٔ خودِ اجرا
  → گزارش فارسی روان + ثبت ماندگار + یادگیری سه‌لایه
```

### فایل‌های قلب

| فایل | نقش |
|---|---|
| `persian_router.py` | واژگان فارسی → زنجیره؛ کل حلقهٔ `route_and_run` |
| `dependency_planner.py` | توپولوژی نیازها + انتخاب عملیات (ثابت + آموخته) |
| `orchestration.py` | اجرا + ۹ جریان + جمع‌آوری شواهد (`produced_stats`) |
| `quality_gate.py` | داوری ضعیف → تلاش رقیب → بهترین حقیقی |
| `arete/run_judgment.py` | حکمت/شهامت/اعتدال/عدالت از دادهٔ اجرا |
| `persian_report.py` | روایت فارسی روان هر نتیجه و هر جریان |
| `run_history.py` + `planner_learning.py` | حافظهٔ یادگیری (زنجیره / عملیات) |

## ۴. خودگردانی (پیشرو، نه فقط واکنشی)

```
«هر روز ساعت ۸ گزارش کامل بده»
→ scheduler.py: پارس فارسی + ثبت ماندگار (جدول schedules)
→ scripts/scheduler_tick.py: تیکِ پیشرو (idempotent)
→ task_install.py: install-tick → Task Scheduler ویندوز هر ساعت بیدارش می‌کند
→ داشبورد: جدول «چه چیزی خودش اجرا می‌شود»
```

قواعد: فقط دو قالب صادق (هر N دقیقه/ساعت، هر روز ساعت H)؛ شکست هم ساعت را
جلو می‌برد؛ تست‌ها هرگز store واقعی را لمس نمی‌کنند (درسِ ۶۸-ردیفی).

## ۷. قواعد صداقت (قفل‌شده در ۱۱۷۴ تست و ۴۹ probe)

1. **absence ≠ success** — نبودِ شواهد، موفقیت نیست (داوری، جریان، پارس)
2. **intent صریح مقدس است** — هیچ inference آن را لگد نمی‌زند
3. **شکست صادق** — SAPI بی‌صدای فارسی → راهنمای نصب، نه wav خالیِ ۴۶ بایتی
4. **read-back** — هر نصب/ثبتِ ادعاشده باید قابل پرسش باشد
5. **echo بی‌ارزش است** — اعلان/گفتار، ساخته‌شده را می‌گویند نه فرمان را
6. **تست، دادهٔ اپراتور را لمس نمی‌کند** — همه‌جا store ایزوله

## ۷.۵. دوام داده (دو فاجعه، یک الگوی نجات)

**فاجعهی ۱:** یک نویسندهی خارجی متن stderr را روی هدر mind.db نوشت (OpenCV) —
رمزآلود «unsupported file format». **فاجعهی ۲:** فعالکردن WAL روی فروشگاهِ
بازسازیشده → صفحات خراب وسط suite، نوشتهها مفقود. هر دو از سر گذرانده شد:

| لایهی دفاع | نقش |
|---|---|
| بکاپ چرخشی در هر tick | با SQLite backup API + تأیید integrity_check — **فاجعهی ۲ را در چند دقیقه برگرداند** |
| گارد هدر موقع باز شدن | DB خراب فوراً با راهنمای فارسی فیل میکند |
| ژورنال DELETE پینشده | WAL برای این پروفایل (اتصالهای کوتاهِ مکرر) بهصورت عمدی خاموش است |
| بستن واقعی هر اتصال | `with sqlite3.connect()` هرگز close نمیکند — `_conn` یک contextmanager واقعی است (commit + rollback + close) |
| ابزار بازیابی | recover_db.py (پارسر صفحات) + rebuild_db.py (replay با نگاشتِ شکل نه ترتیب منطقی) |

قاعدهی طلایی پس از دو فاجعه: **هر تغییر ماندگاری → بلافاصله بنویس، بلافاصله
بخوانِ پس (roundtrip را در همان تست قفل کن) — نوشتنی که خوانده نشود، نوشته نشده.**

## ۷.۷ استاندارد ایستاده (تاجِ ARETĒ)

زنجیرهای که ۳+ بار با داوری ≥۰.۹۰ برده از انتخابات واقعی StandardKeeper
عبور میکند (شامل hard-gate عدالت و refusal baseline — هیچ self-seeding).
از تاریخچهی واقعی: `chart → pdf` با ۱۳۳۱ برد و داوری ۱.۰ — تاج داده شد.

## ۸. وضعیت مهندسی

- **۱۱۷۴ تست** سبز، **۴۹ probe** در gate انتشار (`scripts/verify.py`)
- mypy ratchet = 0 (بدهی صفر)، ruff تمیز
- verify = READY (lint + ratchet + tests + receipt + probes)
- پروب‌های سرتاسری: حلقهٔ فارسی، داوری ARETĒ، برنامه‌ریز+دروازه،
  حلقهٔ ادراک (ساخت→دیدن→فهم→گزارش)، گزارش کامل + داشبورد

---

## ۹. نقشهٔ ادامه (باخواهشِ اپراتور)

- **زمان‌بندی شرطی** — «اگر فایل جدید در پوشه بود…» (folder watcher)
- **گزارش tick در notify** — «۵ کارِ خودکار انجام شد»
- **جریان دهم** — جدول واقعی database → pdf (خواندن حافظه در گزارش)
- **اجرای مسابقه در زمان‌بندی** — دو زنجیرهٔ کاندید، برندهٔ ARETĒ ثبت شود
